# VPN 与翻墙软件分类速查

vpn软件、翻墙软件和梯子软件可以先按 VPN 应用、代理客户端、浏览器扩展分开阅读，再看各自的设备与配置说明。查翻墙工具或好用的vpn时，这个分类用于整理需求，不提供产品次序，也不把一个类别的功能自动分给另一个类别。

## 分类时分别记录系统接口、软件职责与入口形式

Android 应用能借 VpnService 获得读写 IP 包的文件描述符，虚拟接口的地址和路由也在这一过程配置。Apple 的 NEVPNManager 则负责创建、管理 Personal VPN 配置。它们给出了平台层面的能力描述，但不是一份把所有软件分档的产品清单。

HTTP、SOCKS、Mixed 在 mihomo 文档中归到应用代理，TUN 等则归在透明代理及系统捕获类别。这种分类来自内核文档，用于识别不同入站方式。不能把它照搬成每款软件界面上都必须出现的栏目，更不能用来判断产品交付了哪些服务。

本文把 VPN 应用、代理客户端、浏览器扩展作为阅读分组。一个组看产品页面的应用与服务说明，一个组看配置输入及内核关系，另一个组看浏览器入口。分组不是互斥的技术断言，同一项目的资料可能涉及多个层面。

| 阅读分组 | 优先回答的问题 | 不自动补出的结论 |
| --- | --- | --- |
| VPN 应用 | 项目怎样描述自己的应用及服务 | 全部客户端或组件都开源 |
| 代理客户端 | 读取什么配置、调用什么内核 | 安装后随附服务器资源 |
| 浏览器扩展 | 哪些浏览器有对应入口 | 浏览器以外程序也被接管 |

这张表只是阅读顺序，不能替代每个项目的定义。核对类型时，可回到 [mihomo 官方文档站](https://wiki.metacubex.one/) 与 [sing-box 官方文档](https://sing-box.sagernet.org/) 的配置分类，保留文档使用的原始项目名。

## VPN 应用举例只对应页面已经列出的项目

Mullvad 的下载页列有 Windows、macOS、Linux、iOS、Android，官方客户端仓库也同时涉及桌面和移动端。它可以作为页面按平台提供应用的例子，不由平台列表推出未列出的系统门槛。阅读入口用 [Mullvad 官方页面](https://mullvad.net/) 表示。

Mullvad 仓库使用 GPL-3.0，README 又对 iOS App Store 发行版单列 EULA。开源仓库存在与每个发行版本都采用同一许可不是同一句话，例子中的许可条件也不能省略。它的官方隐私自述另有范围，不能仅凭仓库许可替它回答数据处理问题。

Proton VPN 的页面同时列有桌面、手机、浏览器与电视平台入口。这个例子说明产品页面可以按设备组织资料，不表示这些入口拥有完全一致的接管范围。[Proton VPN 免费版官方页面](https://protonvpn.com/free-vpn) 在这里仅作该产品公开说明的指代，本文不展开免费档风险或额度比较。

ExpressVPN 的下载页也列出桌面、手机、浏览器扩展等项目。页面支持某系统与具体协议科普页列出某协议，需要分别核对；其通用协议说明不是产品逐项启用能力的清单。[ExpressVPN 官方页面](https://www.expressvpn.com/) 对应这一例子，不含使用效果评价。

## 代理客户端看输入方式与内核之间的关系

Clash Verge Rev 将自己描述为基于 Tauri 的 Clash Meta 图形客户端，并列有系统代理、TUN、配置管理和可视化规则编辑。其快速入门把导入订阅与开启代理分开写。由此可将“配置怎么进入应用”和“连接怎样交给内核”列成不同阅读项。

FlClash 的项目说明把 mihomo 与 Clash.Meta 两个名称放在内核关系中，配置可由订阅地址或本地文件导入。功能表另外列有覆写脚本、自定义规则、代理组与连接查看等条目。这里保留项目自己列出的能力，不把某项功能写成所有代理软件的共同能力。

v2rayN 的项目介绍强调图形界面与可调用的不同核心，Wiki 另行列出订阅功能。它可以作为“界面、核心、输入资料分别查”的例子；已读到的项目页面没有承诺交付节点或订阅资源，本文不替它加上资源说明。

三个例子的资料入口分别为 [Clash Verge Rev 官方发布页](https://github.com/clash-verge-rev/clash-verge-rev/releases)、[FlClash 官方发布页](https://github.com/chen08209/FlClash/releases)、[v2rayN 官方发布页](https://github.com/2dust/v2rayN/releases)。它们没有被排列为优先顺序，例子的作用是展示怎样从页面寻找配置输入、内核与资源边界。读者关心哪项职责，就读取相应栏目。

## 浏览器扩展按浏览器入口识别，范围留给原文

ExpressVPN 下载页列有 Chrome、Firefox、Edge、Brave 扩展。Proton 的页面也列出 Chrome、Firefox，Windscribe 的功能页列出 Chrome、Firefox、MS Edge。这些是页面已经给出的入口名字，不能在名称之外添加未说明的浏览器版本门槛。

“有扩展”回答了入口形式的问题，却没有在现有资料中完整回答扩展处理哪些程序的数据。因此本文不把扩展概括为整机连接方式，也不写它与桌面应用一定独立或一定联动。没有范围定义时，入口列表保持入口列表的含义。

ExpressVPN 官方组织下有浏览器扩展的开源仓库，也有 Lightway 相关仓库。能确认这些组件公开，不等于其全部桌面和手机客户端代码都公开。范围从组件扩到全部产品，需要另一份明确说明，不能由“开源”标签自行补齐。

这种分开记录也适用于产品选择。需要某个浏览器入口时，记录该浏览器有没有被列出；需要桌面应用时，转读桌面平台说明。两类问题不因出现在同一家产品页面就自动得到同样答案。

## 协议名称不是客户端名称，也不是产品效果

WireGuard 的官方介绍把它称为 VPN。OpenVPN 官方页面把自己描述为通过 SSL/TLS 扩展网络，并特别排除在网页浏览器内运行的网页应用代理定位。这两份定义说明各自项目的定位，不是一张对所有客户端的优劣对照表。

协议页面、客户端页面与平台接口文档各有主语。某个客户端列出多个内核时，不能把某个内核的全部协议列表都算成它当前界面支持的输入格式。需要逐层核对，才知道页面究竟在描述内核、入站、出站还是订阅解析。

v2rayN 的 README 将它描述为 Windows、Linux、macOS 图形客户端，支持 Xray、sing-box 等内核。它的 Wiki 另有支持核心列表与订阅说明，两份页面的栏目并不相同。原项目资料由 [v2rayN 官方发布页](https://github.com/2dust/v2rayN/releases) 指代，这里不展开平台安装步骤。

阅读协议概念时，可分别查看 [WireGuard 官方页面](https://www.wireguard.com/)、[OpenVPN 官方文档](https://openvpn.net/community-resources/how-to/)。文档解释了项目是什么，并没有因此给“好用”设定统一分值。协议名称出现在页面中，也不能单凭名称推出连接速度、服务覆盖或某种应用场景的结果。

## 平台、许可和隐私要采用不同的判断栏目

平台支持需要项目自己的平台表。FlClash 列有 Android、Windows、macOS、Linux，v2rayN 列的是桌面平台；这些文字能用来判断哪类设备有对应项目入口。不能因为它们都处理代理配置，就把手机支持补给桌面项目。

许可需要具体发行范围。Mullvad 对 iOS 商店发行版单列条款，ExpressVPN 公开的是特定组件与扩展仓库；两种情况不能被压成“整套产品全部开源”。有仓库入口、某组件开源、某发行版采用某许可，是可以分别记录的事实。

隐私方面，Mullvad 官方称不记录活动日志，但同页也列付款记录、支持邮件及短时访问日志等说明。ExpressVPN 官方称不记录在线活动与连接 IP 日志，同时提到部分聚合使用数据。保留主语和范围，比只摘下“无日志”更接近各自声明。

本文不把这些声明作成评测结论。平台清单、开源范围和数据自述来自不同栏目，即便出现在同一产品下，也不能互相证明。判断方法是分别找原文，不把其中任一项当作全部信息的替身。

## 把个人需求写成可对应页面的问题

如果问题是“这个项目有没有手机版本”，查平台表即可，不需要从客户端名称猜测。如果问题是“能不能读入已有配置”，则查该客户端的配置输入说明，而不是拿某个协议项目的介绍作答。两个问题的对象不同，阅读资料的入口也不同。

如果问题是“应用是否提供远端资源”，优先找明确的交付声明。v2rayN 已读取页面没有这类资源承诺，就不能仅因功能列表有订阅入口而补出服务内容。页面未提及与页面明示交付是不同状态，应在记录中分开。

如果问题是“哪个浏览器有入口”，按官方列出的浏览器名记录。页面没有完整作用范围定义时，不继续推成全电脑或全设备的结论。本文仅把已有说明对应到问题，没有为未列出的情形设计兼容性判断。

“好用”的讨论至此可以落到设备、输入、接口、发行范围等具体项目。不同需求会关注不同栏，但本页没有给这些栏目赋分。选读过程保留原文的限制和缺口，不用一句形容词替代一组不同性质的信息。

配置管理还可以看项目列出的管理对象。Verge 写有 Merge、Script、语法提示及可视化节点和规则编辑，FlClash 列出编辑器、自定义规则、代理和组。这些条目有助于区分“能导入”与“能在界面内继续编辑”，但不能替任意一种输入格式作兼容保证。

界面之外也有各自的资料。FlClash 的项目说明列出连接、请求、DNS 与日志查看，以及 WebDAV 或本地文件备份恢复；Verge 同样列出 WebDav 配置备份和同步。这些功能涉及资料管理，不能因都有备份字样就宣称两种项目的备份文件可以互换。

内核文档中还可以按栏目区别入站、出站与 Endpoint。sing-box 的 Endpoint 导航列有 WireGuard、Tailscale、OpenConnect Client、OpenVPN Client/Server、MASQUE Client/Server；这个导航本身没有把它们变成某款图形应用已经提供的按钮。读配置类别时保留栏目，读软件功能时保留项目名称，两种查法各有用途。

## FAQ

### VPN 软件和代理客户端必须是互斥分类吗？

本文只是按阅读职责分组。系统接口、内核和应用页面描述不同层面，不能据此断言产品只能属于一个组。

### 客户端有订阅导入，就会赠送服务吗？

输入能力不等于资源交付。v2rayN 已读页面没有承诺赠送这类资源，不能由订阅功能替它补出承诺。

### 浏览器扩展会接管所有软件吗？

本页资料没有取得这种统一范围定义。已确认的是产品页面列出对应浏览器入口。

### 有开源仓库就表示全部版本都开源吗？

需要看仓库与发行许可的实际范围。特定组件公开或商店版本另有条款，都不能删掉范围后转述。

### 协议科普页列出的协议都能在产品里选吗？

ExpressVPN 的协议介绍没有逐一对应实际产品选项。通用协议条目不能替代产品能力清单。

### 这里为什么不直接排个使用次序？

所列来源给出的是接口、平台和项目自述。本文按问题对应资料，没有取得可用于统一排序的依据。
